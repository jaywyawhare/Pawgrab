Rate Limiting

Every API token is limited to a fixed number of requests per minute. The current ceiling is six hundred requests per minute for standard plans and six thousand for enterprise plans. Limits are enforced per token, not per IP address.

Each response includes three headers that describe your current budget: the limit, the number of requests remaining in the window, and the Unix timestamp at which the window resets. Clients should read these headers rather than hard-coding the limit.

When you exceed the limit the API returns a 429 status code with a Retry-After header indicating how many seconds to wait. A well-behaved client backs off for that duration and then resumes. Repeatedly ignoring 429 responses can lead to a temporary block on the token.
